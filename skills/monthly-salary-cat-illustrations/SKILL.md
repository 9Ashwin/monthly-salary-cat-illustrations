# 月薪喵正文配图

将正文中的输入、判断、变换、输出和反馈画成可追踪的结构。默认生成 16:9 PNG，由月薪喵操作其中的装置。

## 按需要读取

- 首次画图前，读 [画面与文字风格](references/style-dna.md) 和 [月薪喵角色](references/monthly-salary-cat-ip.md)，查看原始角色参考后再设计动作。优先使用用户提供的原图；否则直接读取内置的 [角色精灵图](assets/character-reference.webp)。不要用新生成的猫作为后续角色参考。
- 生成前读 [构图与隐喻](references/composition-patterns.md)，根据正文写清环节、连接与猫的操作。
- 写提示词时用 [单图模板](references/prompt-template.md)，将本次关系草案完整带入。
- 生成后按 [检查清单](references/qa-checklist.md) 核对角色和图意。
- 流程或关系图按 [示例索引](references/composition-patterns.md#使用已有示例) 选看 `assets/examples/` 中的月薪喵示例，校准画面密度和表达方式。示例不替代原始角色参考，也不默认作为图像工具输入；纯角色状态图无需这一步。

## 理解内容与选择配图

读取用户给的正文、文档或主题，找出值得解释的因果、步骤、分支、断点、闭环或状态变化。配图数量随内容和用户要求决定，不按段落平均分配，也不凑固定张数。

只要求规划时，输出配图清单：放在哪段后、核心判断、结构与环节、猫的操作、必要的中文标注。不调用图像生成。

明确要求生成时，直接完成配图，不额外等待清单确认。每张图先形成内部关系草案：核心观点、3–5 个功能环节或 2–4 个对比状态、箭头起点与终点、分支或反馈落点、猫的操作、必要标注。按内容取舍，不为凑数增加环节。

如果正文或用户只要求一个角色状态，可以直接画该状态，不虚构输入、输出和回路；下面的流程可追踪要求适用于内容本身包含步骤或关系的图。

**一个核心结构可以包含多个动作。** 保留正文所需的步骤、分支和回路，不能缩成猫的小动作与一句口号。可用多只形象一致的月薪喵表现不同分工或前后状态。

## 单张生成

使用当前 Agent 已启用、支持参考图的图像生成能力，可以是内置工具、已连接的图像服务或现有生图技能；不限定平台、模型或工具名称。遵循所选工具的调用说明，每次生成一张独立图片，无需另启动其他 Agent 或搭建多阶段生成流程。

生成新图时，将原始角色图作为真实图片输入传给工具，不能只在提示词中写文件名。按宿主支持的方式使用本地文件、附件或上传结果，并将本次关系草案写入提示词；只有用户指定布局或编辑对象时，才同时传入对应图片。

安装包内置 `assets/character-reference.webp`，保留原始精灵图的完整内容。查看后直接作为角色参考传入，无需额外下载、安装宠物、登录或分帧。仅在文件缺失或损坏时，按角色文档恢复。

工具不接受 WebP 时，可用现有图片工具将其无损转为 PNG，保留完整画面与透明度；这是格式适配，不另生成角色图。输出尺寸和格式按工具实际支持设置，优先接近 16:9、导出 PNG；保留原始输出，不把改扩展名当作格式转换。

默认纯白背景、深棕描边、奶白与奶茶棕配色。流程或关系图用管道、闸门、轨道、晾绳、抽屉等低科技装置承载功能关系，月薪喵必须正在操作其中的关键环节。主布局使用画布中心与大部分横向空间，约留 25%–35% 空白，不把内容压在底部小角落。可有 5–8 处短标注，按图意决定，不靠删掉关系换取留白。

动作可以改变，但必须保留原型的头身比例、耳顶轮廓、锯齿颊毛、脸部色块和小蓝眼。仓库示例也须先写关系草案，再使用同一提示词模板。

图像生成不可用，或工具无法接收角色参考图时，说明缺少的能力并提供关系草案和提示词，不宣称图片已生成或已按原型校准。不要仅凭 Agent 名称假定某个工具已可用。

## SVG 与原始素材

公开原始素材是 WebP 精灵图，本项目未取得作者的 SVG 原稿。用户明确要求矢量时，可另行整理或描摹 SVG，并标明“从 PNG／WebP 描摹的矢量版”。嵌入栅格图的 SVG 仍是栅格包装，不能称为矢量原图。全量动作素材另行整理，不给日常配图增加矢量化步骤、脚本或依赖。

## 检查与交付

对照原始角色参考、关系草案和生成结果，按[检查清单](references/qa-checklist.md)核对角色与内容。题目要求的步骤、分支、输出和回路都应可追踪。**流程或关系图中，只看得出猫在做什么、看不出内容如何流动，视为失败。** 针对实际偏差修改，不因可选装饰反复重生成。编辑现有图片时保留用户未要求改变的内容。

将最终 PNG 保存到用户指定位置；未指定时使用工作区 `assets/<article-slug>-illustrations/`，按 `01-topic.png` 顺序命名。简短报告每张图的用途和可访问路径，并展示结果。保留可用的原始生成文件，不覆盖用户已有图片。

配图工作流参考 Ian Xiaohei Illustrations；出处与素材说明见同目录 [NOTICE.md](NOTICE.md)。
