# 构图与隐喻

## 先写内部关系草案

生成前写清以下关系，再填提示词，不新增确认轮。仅要求规划时，将草案整理为配图清单。

- **核心观点**：这张图要解释哪个判断或关系。
- **功能环节**：通常 3–5 个，写出每处进入什么、做了什么、离开什么；对比图可用 2–4 个状态替代。
- **连接关系**：逐条写起点 → 终点。分支注明区别，回路注明反馈回到哪一步并改变什么。
- **猫的操作**：在哪个环节做什么，如何影响分流、变换、承接或反馈；多只猫各有分工。
- **必要标注**：输入、判断、输出、分支目的及反馈内容，通常 5–8 处短词。

一个核心结构可以有多个动作。例如“反馈闭环”通常需要来源、判断、产出、承接及回收；不能只画猫拿着意见纸，再写“听听反馈”。

仅表达单个角色状态的请求不必套用流程结构；草案只写状态、触发因素和必要物件即可。内容没有的分支或回路不要补造。

## 让关系变成装置

| 内容关系 | 可用的具象承载 | 需要画清的交互 |
| --- | --- | --- |
| 步骤与承接 | 轨道、管道、晾绳、接力小车 | 上一步的产物实际进入下一步 |
| 判断与分支 | 闸门、分岔轨道、筛网、可转动导流槽 | 谁在判断，每一支通向何种用途 |
| 反馈闭环 | 回收管、传回的纸条、回程绳索 | 从结果回到输入或判断处，方向不可反 |
| 多源汇入 | 不同抽屉、料斗、收集篮 | 来源保持可辨，并在何处汇合 |
| 一源多用 | 模具、拆分台、分装口 | 同一材料怎样变成用途不同的产物 |
| 前后分工 | 人扛与滑轮、手搬与轨道、散放与架子 | 重复工作被谁承担，猫仍在哪判断 |

按正文选一套物件系统即可。装置不必机械真实，但连接在视觉上应成立：进出口要对得上，箭头不要穿过无关物件，也不能用装饰弧线代替真正的反馈。

按[画面风格](style-dna.md#画面)设置横向主布局。输入、处理、输出之间留出间距，必要时把回路放在主线下方；对比图可左右展开。不要靠删步骤制造空白。

猫的操作必须影响内容流动，例如拉杆、换轨、拣选、加工、转交或回收。不要把猫贴在流程框旁，也不要放大角色挤掉需要解释的结构。
