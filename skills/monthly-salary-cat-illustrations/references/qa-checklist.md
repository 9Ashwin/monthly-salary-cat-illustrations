# 检查清单

对照原始角色参考、关系草案与成图检查；角色和内容结构均符合要求，才可交付。

## 角色

- 头身比例仍接近原型，身体短而略方，没有变成巨头小圆身。
- 小三角耳、较平或微凹的头顶、锯齿颊毛仍可辨认。
- 奶白额心三角向下展开，奶茶棕保留在耳与头两侧，没有改成刘海。
- 蓝眼与深棕小嘴足够简练；不存在大高光眼、大水滴眼或明显 W 嘴。
- 短爪、尾巴、领带与该姿态一致，无多余肢体或人类手指。

## 结构与交互

以下按正文和请求实际包含的关系检查。纯角色状态图只需把状态与触发因素表达清楚，不强求流程、分支或回路。

- 题目或正文要求的步骤、分支、断点、对比状态和回路都能在图中找到。
- 沿输入走到输出，可以逐个指出各环节做了什么；不是靠一段标题解释整幅图。
- 每条主线箭头有明确起点和终点，方向正确；装置进出口与流向一致。
- 各分支有可辨认的不同用途；反馈真正从结果回到输入或判断处，不是悬空装饰弧线。
- 猫正在执行判断、变换、分流、交接或回收；操作会影响内容流动。多只猫各有分工。
- 一图一个核心结构；保留说明它所需的多个环节，而不是只留一个小动作和一句标签。

**流程或关系主题的失败信号：看得出猫在做什么，但看不出内容怎么流动。** 同样失败的还有：题目要求三路分流却只剩一条线、闭环没有回到处理处、系统承重只画成一只累猫。

## 版式与文字

- 主结构位于画布中心，利用大部分横向空间；约 25%–35% 留白，各环节互不拥挤，未把画面压在底部小角落。
- 默认横版与纯白背景符合请求；用户另有比例或背景要求时遵循用户。
- 必要短标注足以识别功能，通常可有 5–8 处；中文准确可读，没有多余海报标题、励志口号、错字或伪造数字。
- 流程或关系图用具象物件组织关系，避免整齐矩形框堆成的 PPT，也不只有宠物情绪。
- 构图来自本次正文；示例只用于校准密度与交互，没有照搬不适合当前内容的文案或整套装置。

## 有问题时

| 实际问题 | 修正方向 |
| --- | --- |
| 像另一只白棕猫 | 带回原始角色参考，只修正比例、轮廓或五官偏差 |
| 猫只是装饰 | 把判断、变换或分流操作交给猫，画出操作对流向的影响 |
| 只有小场景，没有内容结构 | 回到关系草案，补齐输入、判断、输出、分支或回路 |
| 箭头悬空或回流方向错误 | 逐条修正起点和终点，使进出口、分支目的与反馈落点一致 |
| 太满或像海报 | 删装饰、大标题与重复说明，保留解释结构必需的环节 |
| 上半幅空、主体挤在角落 | 将主结构移到画布中心横向展开，不只放大猫 |
| 中文错误 | 局部改字；没有信息作用的标签可直接移除 |
| 太像旧示例 | 保留要解释的关系，重选物件与动作 |

优先修正影响身份、内容或阅读的问题；不因可选装饰反复重生成。交付前确认最终文件已保存，未把 PNG 或重绘 SVG 称为作者的矢量原稿。
